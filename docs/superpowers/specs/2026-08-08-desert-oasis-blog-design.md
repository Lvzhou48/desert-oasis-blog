# “沙漠里的绿洲”个人博客设计

日期：2026-08-08
状态：已确认，待实施

## 1. 项目目标

建设一个名为“沙漠里的绿洲”的独立个人博客。它同时承担两种角色：

1. 作为面向外界的内容名片，让访客通过文章逐渐认识作者的专业能力、观察和经历。
2. 作为作者自己的精神角落，长期记录技术、成长、生活与远方。

网站不公开作者真实姓名、正脸或过多私人信息。作者以简短笔名、抽象绿洲符号和克制的介绍保持神秘感。

成功标准：

- 首次访问者能迅速理解博客的主题和气质。
- 文章阅读体验在桌面端和移动端都清晰、安静。
- 作者可以把草稿交给 Codex 完善，确认后以 Markdown 发布。
- 网站不依赖自建账号、数据库或长期运行的后端服务。
- 新文章发布前能自动发现格式、构建和链接问题。
- 源码、已发布文章、自动部署和评论统一由一个公开 GitHub 仓库承载。

## 2. 第一版范围

### 包含

- 首页
- 全部文章页
- 分类页
- 关于页
- 文章详情页
- 站内搜索
- 标签筛选
- GitHub 身份评论
- 定制 404 页面
- 响应式桌面端与移动端布局
- 自动检查与 GitHub Pages 部署
- 单一公开 GitHub 仓库的版本管理

### 不包含

- 自建账号和密码体系
- 在线写作后台
- 简历、项目作品集或求职模块
- 邮件订阅系统
- 广告与用户追踪脚本
- 点赞、收藏、私信等社区功能

## 3. 信息架构

顶部导航固定为：

- 首页
- 文章
- 分类
- 关于
- 搜索入口

移动端将导航折叠为简洁菜单。

### 3.1 首页

首页按以下顺序组成：

1. 博客名称和顶部导航。
2. 一句代表作者的话：“在喧嚣世界里，保留一小片生长。”
3. 匿名化个人介绍：“记录数据工程与 AI，也记录生活、远方，以及那些尚未有答案的思考。”
4. 抽象绿洲图形，不使用真实头像。
5. 4 至 6 篇最新文章，以一张主卡片和多张次级卡片呈现。
6. 前往全部文章的入口。
7. 简短签名式页脚。

### 3.2 文章页

按发布日期倒序展示全部已发布文章，支持关键词搜索、分类和标签筛选。搜索仅覆盖文章标题、摘要、分类和标签，不在第一版引入独立搜索服务。

### 3.3 分类页

固定初始分类为：

- 数据工程和 AI
- 生活与成长
- 远方与见闻
- 随想

分类可在以后随文章积累调整，但第一版文章必须选择且只选择一个主分类；标签可以有多个。

### 3.4 文章详情页

文章详情页包含：

- 标题与摘要
- 发布日期和可选更新日期
- 预计阅读时间
- 主分类与标签
- 正文和目录
- 上一篇、下一篇
- GitHub 评论区

### 3.5 关于页

说明“沙漠里的绿洲”这个名字、写作动机和主题边界。页面不展示真实姓名、正脸、雇主等能够直接识别作者的信息。

### 3.6 404 页面

不存在的地址进入“迷失在沙漠”主题页面，并提供返回首页和浏览文章两个入口。

## 4. 视觉设计

采用已确认的“A · 绿洲杂志”方向：

- 主色：温暖沙色、森林绿、米白。
- 辅助色：少量土金，用于标点、分隔和强调。
- 质感：轻微纸张感、柔和光照和低对比阴影。
- 排版：中文正文优先保证阅读；标题使用有文学感的衬线字体，导航和元信息使用清晰的无衬线字体。
- 图形：使用几何化的沙丘、太阳、水域和植被组成抽象绿洲符号。
- 动效：只使用轻微进入、悬停和滚动反馈，并尊重系统的减少动态效果设置。

页面不能依赖大面积照片建立气氛，避免素材风格不一致。封面图为可选字段；没有封面的文章仍须拥有完整、好看的纯排版卡片。

## 5. 技术架构

### 5.1 网站框架

使用 Astro 构建静态博客。选择理由：

- 适合文章和文档等内容型网站。
- 支持以 Markdown 或 MDX 保存文章。
- 构建时生成静态页面，线上无需应用服务器。
- 内容集合可以对文章元数据进行结构校验。
- 默认减少客户端 JavaScript，有利于加载速度和阅读稳定性。

### 5.2 组件边界

- `SiteHeader`：品牌、桌面导航和移动菜单。
- `Hero`：代表句、匿名介绍和抽象绿洲图形。
- `ArticleCard`：在不同列表中统一显示文章摘要。
- `ArticleList`：负责排序和组合文章卡片。
- `SearchAndFilters`：在浏览器中完成小规模文章索引的搜索和筛选。
- `ArticleLayout`：文章元信息、目录、正文和前后篇导航。
- `Comments`：封装 giscus，不让评论服务耦合到正文组件。
- `SiteFooter`：签名、版权和必要外链。

每个组件只承担一种明确职责；文章数据通过内容集合统一进入列表、分类、搜索和详情页。

### 5.3 内容模型

每篇文章至少包含：

```yaml
title: 文章标题
description: 文章摘要
publishedAt: 2026-08-08
category: 数据工程和 AI
tags:
  - 数据工程
draft: false
```

可选字段包括 `updatedAt`、`cover` 和 `coverAlt`。当存在封面时，`coverAlt` 必填。发布日期使用带时区含义的统一日期格式，页面展示按 Asia/Shanghai 处理。

### 5.4 评论

使用 giscus 将每篇文章映射到 GitHub Discussions：

- 读者通过 GitHub OAuth 授权后发表评论。
- 评论与反应保存在 GitHub Discussions，不进入博客数据库。
- 作者通过 GitHub 管理、隐藏或删除评论。
- 使用文章稳定路径进行映射，避免修改标题后丢失评论关联。
- giscus 延迟加载，评论区接近视口时才加载。
- 评论组件失败时显示说明和前往对应 Discussion 的备用入口，不影响正文阅读。

giscus 直接使用公开的网站源码仓库 `Lvzhou48/desert-oasis-blog` 的 Discussions，不另建评论仓库。

## 6. 写作与发布流程

标准流程：

1. 作者向 Codex 提供草稿、提纲、零散想法或整理后的语音文本。
2. Codex 在不改变作者核心观点的前提下完善结构和语言，并明确标记补充或推断内容。
3. 作者确认最终稿。
4. Codex 创建可公开的 Markdown 文章，补齐标题、摘要、分类、标签和日期，并设置 `draft: false`。
5. Codex 运行内容校验、构建、链接检查和页面验收。
6. 检查通过后提交到 Git。
7. 默认分支更新触发 GitHub Actions，构建产物发布到 GitHub Pages。

作者确认前的私人草稿只保存在对话、本地临时文件或仓库之外，不提交到 Git。`draft: true` 只用于本地预览和防止页面生成，不提供保密能力；公开仓库中即使标记为草稿，文件内容仍然可见。发布检查必须拒绝包含已跟踪 `draft: true` 文章的提交。

## 7. 部署和域名

- 源码仓库固定为公开仓库 `Lvzhou48/desert-oasis-blog`。
- 第一版部署到 GitHub Pages，初始项目站点地址为 `https://lvzhou48.github.io/desert-oasis-blog/`。
- 以后购买域名时，通过 Pages 配置绑定并启用 HTTPS。
- GitHub Actions 将构建和部署拆成依赖步骤；只有构建成功才执行部署。
- 构建失败时，线上保留最后一次成功发布的版本。
- 同一仓库启用 Discussions，并供 giscus 存储文章评论。

公开仓库不保存真实邮箱、密钥、私人草稿或其他敏感信息。提交作者邮箱使用 GitHub 设置页提供的 `noreply` 隐私邮箱；首次推送前把当前工作快照整理为一个新的公开根提交，不上传包含非隐私邮箱的本地历史。

## 8. 异常与降级

- 元数据缺失或分类非法：构建失败并指出文章文件和字段。
- 本地草稿存在：允许本地构建但不生成公开入口；发布检查发现已跟踪草稿时拒绝发布。
- 封面缺失：改用纯排版卡片，不显示破损图片。
- 内部链接失效：发布检查失败。
- 搜索脚本不可用：文章列表和分类导航仍可使用。
- giscus 不可用：正文正常展示，评论区显示备用链接。
- 地址不存在：返回定制 404 页面。
- 部署失败：保留现有线上版本，并在 GitHub Actions 中留下失败记录。

## 9. 验收与测试

实施完成后至少验证：

- 首页、文章、分类、关于、详情和 404 页面均可生成。
- 四个初始分类都有正确的路由或筛选入口。
- 草稿不会出现在任何公开索引中。
- 发布检查会拒绝包含已跟踪 `draft: true` 文章的公开提交。
- 搜索和标签筛选能返回正确文章，并能清空条件。
- 上一篇、下一篇不会指向草稿。
- giscus 配置正确，失败时存在降级提示。
- 内部链接检查通过。
- 生产构建通过。
- 手机、平板和桌面主要宽度下没有横向溢出或导航遮挡。
- 键盘可操作导航、搜索、筛选和移动菜单。
- 标题层级、颜色对比、图片替代文本和减少动态效果设置符合基础可访问性要求。
