# 内容与测试解耦设计

## 目标

作者以后可以新增、修改或删除任何公开文章，而不必同步修改测试代码。日常发布仍保持“草稿 → 预览 → 作者明确确认 → 发布”的流程。

## 方案

测试不得再写死真实文章的文件名、标题、分类、标签或 URL。

- 内容构建测试从构建产物中发现任意一篇公开文章页，再验证评论备用入口和可选评论配置。
- 浏览器测试从网站的公开搜索索引或文章列表发现当前文章，并以该文章验证详情页、搜索、分类、RSS 与相邻文章相关行为。
- 当没有公开文章时，测试验证首页、文章列表、分类、RSS 的空状态；不要求存在文章详情页。
- 纯粹的组件规则（例如标签序列化）继续在独立单元测试中使用合成数据，而不是借用真实文章。

## 不采用的方案

- 不保留一篇无法删除的公开“测试文章”，避免把测试需求混入博客内容。
- 不删减已有内容行为测试，保留搜索、分类、RSS、评论备用入口与响应式页面的回归覆盖。

## 发布体验

作者只需把初稿交给 Codex。Codex 负责整理、隐私检查和预览；只有在作者明确说“确认发布”后，才提交并推送到 `main`。自动检查在后台运行，但不再要求作者维护测试样本。

## 验收标准

1. 删除现有公开文章后，不修改测试文件也能通过完整验证。
2. 新增任意公开文章后，不修改测试文件也能通过完整验证。
3. 零篇公开文章时，完整验证仍能通过，并检查公开页面的空状态。
4. 所有现有公开内容安全门禁和 GitHub Pages 发布流程保持不变。
